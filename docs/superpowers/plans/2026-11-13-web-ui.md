# Downloader Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 downloader 守护进程内嵌默认监听 `0.0.0.0:8000` 的 Web 服务，提供任务创建、删除、开始、暂停、清空完成任务和分页进度查询。

**Architecture:** 新增任务管理器作为 IPC 和 HTTP 的共同后端，集中处理 SQLite、调度器和协议生命周期；Web 模块只负责 HTTP/JSON/静态资源，前端通过 REST API 定时轮询。HTTP 服务在独立线程运行，关闭配置时不创建监听端口。

**Tech Stack:** ISO C99、CMake、clib、SQLite3、libcurl、POSIX sockets、原生 HTML/CSS/JavaScript。

**Spec:** `docs/superpowers/specs/2026-11-13-web-ui-design.md`

## Global Constraints

- Web 默认开启，默认监听 `0.0.0.0:8000`。
- `enabled = false` 时不创建 HTTP 监听线程，也不打开 Web 端口。
- IPC 和 HTTP API 必须共用任务管理器，不各自实现任务语义。
- HTTP 第一阶段只支持 GET、POST、DELETE、JSON 请求体和 HTTP/1.1 短连接。
- 页面使用定时轮询，不实现 WebSocket。
- 默认监听 `0.0.0.0`，允许局域网访问；部署时应结合防火墙和网络边界控制访问范围。
- 优先使用 clib 的内存、字符串、JSON、线程、同步、路径和文件接口。
- downloader 自有头文件与 `.c` 文件放在同一源码目录，不新增 `include/` 目录。
- 不依赖真实公网服务测试；HTTP 测试使用回环地址或本地 fixture。

## Review Focus

- Web 配置关闭时，端口不能被占用，守护进程仍应正常启动。
- 绑定 `0.0.0.0:8000`、端口被占用和父目录/资源文件缺失时，必须返回清晰错误并正确释放线程。
- 非法 HTTP 方法、路径穿越、超大请求头、超大 JSON 请求体和无效 JSON 必须被拒绝且不能崩溃。
- 分页参数为 0、负数、超大值或非数字时，必须使用明确的边界策略并返回稳定 JSON。
- 删除、暂停、开始与下载完成并发发生时，SQLite 状态、临时文件和协议 worker 不能产生悬挂任务。
