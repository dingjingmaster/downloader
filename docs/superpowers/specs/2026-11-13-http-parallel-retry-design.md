# HTTP 三线程分片、Web 速度与无限网络重试设计

## 意图
1. HTTP(S) 大文件使用 3 个并发连接分段下载，并支持跨暂停/重启/网络中断的断点续传。
2. Web 任务列表显示实时下载速度。
3. 所有任务遇到网络类临时错误时无限重试，直到完成；永久错误（认证、404、证书、磁盘满、内容非法）仍失败。

## 决策（已与用户确认）
- 仅 HTTP(S)、文件大小已知且支持 Range、大小 ≥ 1 MiB 时启用 3 连接；否则单流回落。
- 分片写入 `<temp>.segments/segN`，元数据（最终 URL、大小、校验器、分片范围、已 fsync 字节）写入同目录；完成后拼接到 `tempPath`，复用核心 fsync+原子提交与 sidecar 清理。
- 服务器不支持 Range/返回 200 时整文件单流重下。
- 网络无限重试由任务管理器统一调度：retryable 由适配器判断（HTTP 5xx/429/超时/连接错误等），指数退避封顶 60s，任务保持排队/下载状态并累计重试次数。
- 守护进程重启后，之前处于 queued/downloading 的任务自动恢复；用户主动暂停的不自动恢复。

## 非目标
- FTP/SFTP/aria/media/SMB 的多连接分片（仍按各自协议引擎能力）。
- 分片跨服务器内容变化继续拼接；身份变化必须重下。
